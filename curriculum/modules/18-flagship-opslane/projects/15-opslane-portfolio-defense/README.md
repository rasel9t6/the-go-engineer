## Mental Model

The portfolio defense is the capstone presentation — like a thesis defense in academia, it proves not just that you built something, but that you understand why you built it that way and can reason about alternatives.

## Visual Model

```text
input -> concept boundary -> behavior -> observable result
```

## Machine View

Under the hood, interviewers evaluate four dimensions: technical depth (do you understand the concepts?), architectural thinking (can you reason about trade-offs?), communication (can you explain clearly?), and growth mindset (can you identify improvements?).

## Code Walkthrough

Read the code from top to bottom. Connect each line to the mental model above. The important question is not only what the line does, but why the program needs that line.

## Try It

1. Run the command exactly as shown.
2. Change one input.
3. Predict the output before running again.
4. Explain the result in your own words.

Common mistakes:

- Memorizing code instead of understanding architectural trade-offs.
- Not being able to explain why a specific technology or pattern was chosen.
- Defensiveness when asked about design limitations or potential improvements.

## In Production

Top tech companies evaluate candidates through system design interviews, architecture reviews, and code walkthroughs. The Opslane portfolio defense simulates this process with a real Go production application.

## Thinking Questions

1. What problem does this concept solve?
2. What would break if this concept were removed?
3. How would you test the behavior?
