# Shell + Git Lab — Rubric

## Criteria

### 1. Shell fluency (25%)

| Level | Score | Description |
|-------|-------|-------------|
| Excellent | 5 | Correctly navigates filesystem, creates/deletes files, uses pipes and redirects without errors. Explains what each command does. |
| Proficient | 3 | Most commands correct; minor errors in path resolution or syntax. Can explain most commands. |
| Developing | 1 | Struggles with basic navigation and file operations. Cannot explain command behavior. |
| Not attempted | 0 | No shell work demonstrated. |

### 2. Git workflow (30%)

| Level | Score | Description |
|-------|-------|-------------|
| Excellent | 5 | Complete Git workflow demonstrated: init, add, commit, branch, merge, conflict resolution. Meaningful commit messages. Clean history. |
| Proficient | 3 | Basic workflow works (init, add, commit) but branching or merging has errors. Commit messages are minimal. |
| Developing | 1 | Can initialize a repo and make commits but cannot branch or merge. |
| Not attempted | 0 | No Git work demonstrated. |

### 3. Code quality (20%)

| Level | Score | Description |
|-------|-------|-------------|
| Excellent | 5 | Go code compiles, all tests pass, idiomatic Go style, proper error handling, clear function signatures. |
| Proficient | 3 | Code compiles and passes most tests. Minor style issues or missing error handling. |
| Developing | 1 | Code compiles but fails tests. Significant style or correctness issues. |
| Not attempted | 0 | No code written. |

### 4. Conceptual understanding (15%)

| Level | Score | Description |
|-------|-------|-------------|
| Excellent | 5 | Clearly explains why Git uses a three-state model, how branches work as pointers, and how HTTP request-response cycle functions. |
| Proficient | 3 | Can explain most concepts but has gaps in deeper understanding (e.g., cannot explain merge vs rebase). |
| Developing | 1 | Can name concepts but cannot explain how they work or why they matter. |
| Not attempted | 0 | No explanation provided. |

### 5. Production readiness (10%)

| Level | Score | Description |
|-------|-------|-------------|
| Excellent | 5 | Code includes error handling for edge cases, README is clear, and the solution follows professional Go conventions. |
| Proficient | 3 | Basic error handling present. README is present but could be more detailed. |
| Developing | 1 | Minimal error handling. README missing or incomplete. |
| Not attempted | 0 | No production considerations. |

## Scoring guide

| Total points | Grade |
|--------------|-------|
| 20-25 | Exceeds expectations |
| 15-19 | Meets expectations |
| 10-14 | Needs improvement |
| 0-9 | Incomplete — retake recommended |
