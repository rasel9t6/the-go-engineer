# Golden files

## Mission

Understand and apply Golden files in the context of professional Go software engineering.

## Prerequisites

- core-06-06

## Mental Model

A golden file is like a master recording of expected output. The test plays back the code, records the output, and compares it to the master recording. If they match, the test passes. If not, either the code or the master needs updating.

## Visual Model

```text
input -> concept boundary -> behavior -> observable result
```

## Machine View

Golden file testing typically uses `flag` for the update flag, `os.ReadFile`/`os.WriteFile` for file operations, and string/byte comparison for the diff. Go 1.24's `testing/golden` package provides a standardized implementation.

## Try It

2. Change one input.
3. Predict the output before running again.
4. Explain the result in your own words.

Common mistakes:

- Hand-writing expected output files -- they should be generated by running the test once.
- Not updating golden files when expected output changes -- tests fail silently.
- Storing large binary files in golden files -- prefer text formats.
- Not using -update flag workflow for maintaining golden files.

## In Production

Golden files are used for testing code generators, formatters, serializers, and any code that produces predictable output. They prevent regression in output format.
